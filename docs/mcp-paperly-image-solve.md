# Paperly 2.3.0：框选解题改为截图识图，并修复圈题框残留

## 总体目的
用户反馈两个问题：
1. 辅助模式里圈题解题后，圈题框一直留在页面上，影响观感；
2. 有些文档排版乱，本地 OCR 识别不准。用户建议改成：截取框选区域的图片，交给 AI 识图解题。

## 总体规划
1. 阅读项目（README、AiClient、PageView、ReaderViewModel、Settings），定位问题 —— 完成
2. 修复圈题框残留 —— 完成
3. 解题改为只发截图给视觉模型，不再依赖 OCR —— 完成
4. 编译、原位安装到真机、写日志 —— 完成（真机上的实际效果待用户确认）

## 操作详情
- 修改前的文件和 2.2.2 APK 备份在 `备份_2.3.0修改前_20260928/`。
- 圈题框残留的原因：`PageView.kt` 对所有 SOLVE 项都会画圆角框（未聚焦时 alpha 0.35），所以框永远不会消失。
  - 修复后只在 `loading`（解答中）时画虚线框，出结果后立即消失。
  - 新增：松手后、确认前，把待发送区域画成虚线框（`pendingLasso`），点"截图发给 AI 解题"或"取消"后消失。
- 截图解题：
  - `AiClient.solve(s, jpeg)` 去掉了 OCR 文本参数和"没有视觉模型就发 OCR 文字"的分支，改为始终发送截图。
  - 模型选择：优先用"解题模型"；留空时按 Base URL 匹配 PRESETS 里的视觉模型（`defaultVision`）；DeepSeek 这类没有视觉模型的服务会给出明确提示。
  - 提示词改为：先识别题干，再给最终答案和推导。
- `ReaderViewModel.solveRegion`：
  - 不再读取 OCR 结果；标签改为"第 N 页 · 框选截图解题"。
  - 渲染分辨率从 2000 提高到 2400，截图长边上限从 1600 提高到 1800，识图更清晰。
  - 缓存 key 加了 `|img|` 标记，避免命中旧的 OCR 解答；`regenerate` 同步修改。
- 设置页文案：解题模型改为"识图，需支持图片；留空按服务自动选择"；DeepSeek 预设的说明同步更新。
- 版本号改为 2.3.0 / versionCode 7。
- 编译：`:app:assembleDebug --offline` 成功（BUILD SUCCESSFUL in 51s），没有新增警告。
- 交付：`Paperly-2.3.0-debug.apk`（57,415,425 字节，SHA-256 dee0ebdf…7e65a23）。已用 `adb install -r` 原位安装到 d8a4be7c，显示 Success，数据保留。
